# RC24 adversarial review

Reviewed configuration edits against active attempts, immutable native approval cases, concurrent browser/CLI writers, legacy scheduler behavior and model-protocol routing. Settings snapshots use an OS lock, revision comparison and atomic replace. The worker samples settings at an attempt checkpoint and never changes a running attempt. Initial settings are part of the atomic inbox record; elevated approval digests bind them. Later elevated edits remain prohibited. Scope, permissions and acceptance commands are not editable through the settings schema.

A separate planning subprocess has no execution tools and shares the cycle deadline. It calls only the local provider in local mode, with no cloud fallback; a failed/empty plan prevents worker dispatch. Cloud/worker model choices are independent. Task gateway requests, including delegate requests, are pinned to the selected worker model; native system messages are preserved while additive task instructions are delivered in the protocol's system channel. Auto retains its free-only pool; explicit compatible cloud models are now available to the native wrappers.

The legacy routing/scope-review service is separate from planning. Its demand projection now reads the same task-setting overlay: changing an unsupervised legacy task to cloud planning does not needlessly start the local router; a configured local scope reviewer still does. Terminal refresh pauses while a modal is open and the settings footer stays visible, fixing a pilot-discovered save-button clipping issue.

Git views are read-only, bounded and clearly labelled as the current working tree, including existing/concurrent edits. No staging/reset/commit occurs. External diff/textconv hooks and optional index writes are disabled in the new reader. Untracked contents are omitted; common secret patterns are redacted but this is not comprehensive secret detection. Attempt observations record bounded changed-file fingerprints, not exclusive agent authorship.

Validation includes optimistic conflicts, forbidden policy fields, frozen privilege cases, initial queue snapshots, local-no-fallback routing, independent planner/worker models, planner-failure dispatch suppression, worker/system gateway payloads, legacy local-router demand, authenticated APIs, real-browser settings/changes/navigation across1440/768/390, and Textual settings interaction. Responsive inspector:0 failures, one known SVG-navigation/chart-hue false positive. Literal task IDs/output account for the monospace lint warning.

Limitations: existing ordinary continuous swarms are editable; finished/elevated snapshots need a new task/case. Older running workers must be gracefully restarted before accepting settings. Model suggestions are configured/default IDs rather than quota guarantees. Local models must already be running. Separate planning is a text plan, not a new native multi-agent implementation for the six portable engines. Project observations are bounded and may omit transient/restored edits.
